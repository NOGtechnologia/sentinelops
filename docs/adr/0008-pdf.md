# ADR-0008: PDF-Berichte mit fpdf2

## Kontext

Die Spezifikation nennt WeasyPrint (13). A5 verlangt reproduzierbare Berichte (PDF-Text
identisch). WeasyPrint benötigt native Bibliotheken (Pango, HarfBuzz, GDK-PixBuf), die unter
Windows und in schlanken Containern aufwendig sind, und rendert HTML – was für Logdaten eine
zusätzliche Escaping-Ebene erzwingt.

## Entscheidung

**fpdf2** (reines Python, LGPL-3.0, unverändert genutzt): PDF wird direkt aus dem
Bericht-Datenmodell gezeichnet, nicht aus HTML. Feste Metadaten (Erstellungsdatum aus dem
Bericht, Producer, Titel), eingebettete selbst gehostete Schriften (Inter, JetBrains Mono,
DejaVu Sans als Fallback). Logdaten werden als Text gesetzt – nie interpretiert.

## Alternativen

- WeasyPrint: native Abhängigkeiten, HTML-Pfad, schwerer reproduzierbar.
- ReportLab: Open-Source-Teil ausreichend, aber größere API und BSD-Lizenz ohne Vorteil hier.

## Konsequenzen

Layout ist schlichter als bei HTML/CSS. Text-Reproduzierbarkeit ist durch A5 und Unit-Tests
abgesichert.
